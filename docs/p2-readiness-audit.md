# P2 启动门槛审计

日期：2026-06-25

结论：可以进入 P2 开发。当前结论来自内部自动化试玩、内容完整性测试、构建验证和 e2e 冒烟测试；真实玩家留存数据尚未接入，因此后续 P2 平衡仍要保留可调参数和快速回滚空间。

## 审计项

- 第一阶段核心闭环：`p1_loop.test.ts` 覆盖普通快递、终极胶带快递、保险柜、报废汽车、危险导弹、撤退、事故和下一周目信息保留。
- 场景目标理解：e2e 冒烟测试进入正式场景后验证 `p1-campaign`、Pixi 舞台、热区和结果弹窗；非快递目标通过多视角和部位热区运行。
- 事故和多周目：导弹事故、远程试探、撤退三类路线均有自动化用例，事故档案、传闻、伤疤和世界变化会跨周目保存到 runtime meta。
- 架构扩展性：目标、部位、视角、风险、奖励、工具、机械已经通过内容 schema 和 runtime actions 驱动；P2 需要把现有 P1 注册表推广为全局注册表。
- 内容 schema：Zod schema 已覆盖核心内容对象；P2 只需要扩充枚举和新增黑市委托/路线字段，不能绕开 schema 写硬编码内容。
- Pixi 资源管线：`SceneApp` 已能挂载运行时目标并随状态刷新；P2 可先复用现有 `/game-art` 资源，再替换精细资源。
- 存档迁移：旧 store 已能同步到新 runtime，`repro_oldsave.test.tsx` 仍在测试集中；P2 新字段必须提供默认值，避免旧档缺字段崩溃。
- 技术债：高风险债务已列入 `ARCHITECTURE.md` 和 `docs/legacy-migration-inventory.md`，P2 首个任务就是统一内容注册表，避免继续扩大 P1 专用引用。

## P2 开发约束

- P2 目标必须通过传闻、事故档案、信誉、目标完成记录或卖家关系解锁，不能一轮内全开放。
- 黑市、厂房、远征、巨型形态和终局必须共用同一套目标/部位/风险/奖励循环。
- 任何 P2 伏笔可以显示为 locked/silhouette，但不可伪装成已完成玩法。
- 每次完成 TODO 后同步更新 `DEVELOPMENT_TODO.md`。
